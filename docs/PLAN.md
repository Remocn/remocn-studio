# remocn studio — план развития и монетизации

> Рабочий документ владельца проекта. Написан 2026-07-30, по состоянию репозитория на
> коммит `8022b59`. Дизайн-запись прототипа — [Remocn/remocn#218](https://github.com/Remocn/remocn/issues/218);
> этот документ смотрит дальше: что делать после того, как костяк готов, и на чём проект

## 1. Где мы сейчас

Костяк приложения реально собран, и это больше, чем «скелет»:

## 2. Карта продуктов remocn

Монетизацию нельзя планировать для studio в отрыве от остального. Продуктов фактически три:

| Продукт | Что это | Статус | Роль в модели |
| --- | --- | --- | --- |
| **remocn** (remocn.dev) | shadcn-реестр компонентов для Remotion + agent skill + доки | Живёт, open source | Воронка: SEO, доверие, комьюнити. Бесплатное ядро |
| **remocn studio** (этот репозиторий) | Локальное desktop-приложение: Claude пишет настоящий TSX, превью и экспорт | Прототип, MIT | Флагманский продукт для монетизации |
| **studio.remocn.dev** | Hosted spec-driven веб-редактор (RENDER_SDK.md §13) | Набросок | Дальний горизонт; не смешивать со studio |

Ключевая связка: **реестр приводит людей, studio их конвертирует.** Человек находит
компоненты, пробует «Setup with AI» из README реестра — а studio это тот же сценарий,
но в один клик и без терминала. Прямо сейчас эта воронка не оформлена: на remocn.dev
нет страницы studio, README studio называет его «personal use».

## 3. Позиционирование и аудитория

**Кто платит.** «Solo builders and small teams who need a product demo video shipped
today» — формулировка реестра, и она же — платящая аудитория studio:

1. **Инди-разработчики / основатели** — демо продукта, промо фич, ролики для лендинга
   и соцсетей. Уже имеют подписку Claude Pro/Max (обязательное требование studio —
   это фильтр, но и квалификация: у аудитории есть привычка платить за инструменты).
2. **Devrel и продуктовые команды** — регулярные фич-анонсы, changelog-видео.
3. **Агентства/фрилансеры** на motion-графике для tech-клиентов.

**Против кого играем.** Не против CapCut/Descript (другая аудитория), а против:
«девелопер делает демо в After Effects / Screen Studio / вручную в Remotion».
Отличие studio: результат — **код в git**, правится словами, воспроизводим, брендируем
токенами. Это «Claude Code для видео», а не «ещё один редактор».

**Ограничение аудитории, которое надо признать честно:** требования «установлен и
залогинен Claude Code + bun + Rust-совместимая среда» сужают рынок до разработчиков.
Для этапа A–B это нормально (см. дорожную карту); расширение за пределы разработчиков —
это уже hosted-продукт, отдельное решение.

## 4. Дорожная карта

Цель: закрыть DoD эпика #218. Без экспорта продукт не завершает свою же фразу

Цель: любой разработчик с Claude Code ставит studio за 5 минут и получает первый mp4

- [ ] **Подпись и нотаризация macOS.** Сейчас бандл не подписан — Gatekeeper убивает

  установка.
- [ ] **Онбординг первого запуска**: экран «нет Claude Code / нет bun / не залогинен»
  со ссылками (расширение #228 на уровень приложения, не папки).
- [ ] **Шаблоны при создании проекта**: сейчас один шаблон; 3–5 стартовых сценариев
  (product demo, feature announce, social clip, slide-style explainer) — из компонентов
  реестра. Это же будущая витрина премиум-контента.
- [ ] **Crash reporting + opt-in телеметрия** (минимум: версия, ОС, факт экспорта).
  Без этого невозможно будет обосновать ни roadmap, ни цену. Строго opt-in, локальный
  продукт обязан оставаться приватным по умолчанию.
- [ ] **Лендинг studio на remocn.dev** + скачивание + 90-секундное демо-видео
  (сделанное самим studio — это и есть маркетинг).
- [ ] Снять «Status: early prototype, personal use» из README, когда A закрыт.

### Этап C — монетизируемый релиз 1.0 (3–6 месяцев)

Цель: первый доллар. Детали — в разделе 5; здесь продуктовая часть.

- [ ] **Премиум-шаблоны** как контент-канал: приватный shadcn-реестр с токеном —

- [ ] Стабилизация: версия 1.0 должна переживать обновления Remotion (риск — пять

### Этап D — расширение (6–12 месяцев, по сигналам, не по календарю)

- **Windows/Linux порт** — в коде нет macOS-специфики намеренно (#218), но нужно

- **Экспорт-пресеты под платформы** (веса/размеры под X, YouTube, LinkedIn), пакетный

  пока desktop не выйдет на устойчивые продажи. Два продукта одновременно — способ
  не доделать оба.

## 5. Монетизация

### 5.1 Принципы

1. **Ядро остаётся открытым.** Репозиторий уже MIT и публичен — это не отменить задним
   числом, и не нужно: открытость — канал доверия и дистрибуции в dev-аудитории.
   Монетизируется удобство, контент и сервис, а не сам код.
2. **BYO Claude.** Пользователь платит Anthropic сам (Pro/Max). Мы не перепродаём
   токены — нет ни маржи-минус-инференс, ни риска изменения цен API. Это главное
   структурное преимущество модели: **себестоимость обслуживания пользователя ≈ 0.**
3. **Платить должно быть за что-то осязаемое**: время (шаблоны), результат (экспорт-фичи,
   облачный рендер), поддержка (обновления). Не за искусственные замки на том, что
   уже работает.
4. **Не монетизировать то, что дешевле сделать руками рядом.** Всё, что пользователь
   легко повторит в Claude Code без studio, — плохой paywall.

### 5.2 Варианты — разбор

| Вариант | За | Против | Вердикт |
| --- | --- | --- | --- |
| **A. Платная Pro-лицензия приложения** (единоразово + год обновлений, модель Sublime/Screen Studio) | Понятно dev-аудитории; инфраструктура обновлений уже есть; нулевая себестоимость | Нужен Free/Pro-водораздел; код открыт — честные могут собрать сами (на практике для desktop это малый процент) | **Основной канал.** |
| **B. Премиум-шаблоны и пакеты компонентов** (приватный реестр) | Прямая монетизация сильной стороны (реестр); работает и без studio, для всех пользователей remocn; проверенная модель (Tailwind UI и премиум shadcn-реестры) | Нужен постоянный выпуск контента; риск каннибализации бесплатного реестра | **Второй канал, запускать вместе с A.** |
| **C. Подписка на приложение** | Предсказуемый MRR | Подписка на локальный инструмент без серверной части раздражает dev-аудиторию; отток | Не как старт. Возможна позже как «Pro + облако». |
| **D. Облачный рендер** | Реальная серверная ценность → честная подписка/метеринг; путь к пользователям без мощной машины | Инфраструктура и её стоимость; лицензия Remotion для SaaS-рендера (см. 5.5); конкуренция с Remotion Lambda «сделай сам» | Этап D, после валидации спроса. |
| **E. Hosted studio (SaaS)** | Самый большой TAM (не только разработчики) | Другой продукт целиком (см. #218 — «two share a name and nothing else»); инференс за наш счёт или BYO-key-стена | Отдельное решение, не раньше чем через год. |
| **F. Спонсорство/донаты** | Уже есть кнопка | Не бизнес; сотни $/мес в лучшем случае | Фон, не стратегия. |

### 5.3 Рекомендуемая модель: Free + Pro + Templates

**Free (open source, навсегда):**
- всё, что есть сегодня: чат, превью, inspect, snapshot, история, скаффолдинг;
- экспорт mp4 — **бесплатно**. Экспорт — это DoD продукта; замок на нём делает
  бесплатную версию демо-версией и убивает сарафан. Бесплатный полный цикл —
  то, что понесут по соцсетям.

**Pro (лицензия ~$79–99 единоразово, включая год обновлений; продление ~50%):**
- экспорт-пресеты и пакетный рендер (варианты размеров/платформ за один заход);
- бренд-кит (цвета/шрифты/логотипы как контекст агента);
- прозрачность/про-форматы (WebM/ProRes с альфой — фича для настоящей работы);
- приоритетная поддержка;
- дальше — всё «командное» и «конвейерное».

Водораздел: **Free = сделать видео, Pro = делать видео регулярно.** Порог обхода
(собрать из исходников) сознательно принимаем: платящий сегмент ценит время, а не
невозможность обхода.

**Templates (независимо от Pro):**
- пакеты $29–49 или «all-access» ~$99/год: готовые сценарии видео (product demo,
  launch video, changelog, лендинг-хиро) на компонентах реестра, устанавливаются
  и в studio (кнопка «New project from template»), и через `shadcn add` без studio;
- это же контент-маркетинг: каждый шаблон — демо-ролик.

**Ценовые ориентиры** (проверить на первых 20 покупателях, не раньше):
Screen Studio $89 (прямой аналог по аудитории и жанру), Sublime $99, Tower ~$69/год.
Точка входа $79 единоразово выглядит безопасной; подписку не вводить, пока нет
серверной ценности.

**Порядок запуска:** бета (B) бесплатна целиком → на 1.0 включается Pro-водораздел
для *новых* фич (ничего работавшего не отнимать) + первый пакет шаблонов.

### 5.4 Грубая экономика

Себестоимость на пользователя ~0 (инференс — его подписка, рендер — его машина).
Постоянные затраты этапа C: Apple Developer $99/год, мерчант ~5% + $0.5/транзакция,
домен/лендинг — копейки. Значит **точка безубыточности — буквально первые продажи**,
и вопрос не в экономике, а в дистрибуции. Реалистичный ориентир первого года для
side-project-темпа: сотни лицензий (реестр уже даёт канал), т.е. цель этапа C —
не «жить с этого», а подтвердить willingness-to-pay и найти повторяемый канал.

### 5.5 Юридические ограничения — проверить до этапа C

Это блокеры запуска продаж, дешёвые сейчас и дорогие потом:

1. **Лицензия Remotion.** Remotion — source-available: бесплатна для физлиц и компаний
   до определённого размера, дальше нужна Company License. Studio сознательно **не
   бандлит** Remotion (плеер и рендерер резолвятся из `node_modules` проекта
   пользователя) — этот дизайн, вероятно, оставляет лицензию обязанностью пользователя,
   как у любого редактора кода. Но продавать коммерческий продукт, чья ценность
   целиком построена вокруг Remotion, стоит только после письменного ответа команды
   Remotion (они отвечают охотно; возможен и партнёрский интерес). Строка про
   «personal use» в README поставлена не случайно — снять её можно только вместе
   с этим ответом.
2. **Условия Anthropic.** Studio использует подписочную авторизацию залогиненного
   Claude Code через Agent SDK. Для личного инструмента это ровно задуманный сценарий;
   для *продаваемого* приложения нужно перечитать Anthropic Usage Policy / Commercial
   Terms на момент запуска (они менялись) и предусмотреть **запасной вход по API-ключу**
   — он же снимает зависимость от того, что «Claude Code установлен и залогинен».
3. **MIT уже выдан.** Историю не перелицензировать. Варианты для Pro-кода: отдельный
   закрытый репозиторий/модуль, или open-core с Pro-фичами вне MIT-дерева. Решить до
   первой Pro-фичи, чтобы не выковыривать код потом.
4. **Шаблоны и шрифты.** Премиум-шаблоны тянут шрифты/ассеты — лицензии на
   редистрибуцию проверять на каждом пакете.

## 6. Риски

| Риск | Вероятность | Удар | Смягчение |
| --- | --- | --- | --- |
| Anthropic меняет правила подписочной авторизации для SDK | средняя | фатальный для текущей схемы | вход по API-ключу как first-class опция (этап C) |
| Обновление Remotion ломает именованные внутренние модули (warm render, entry-слот) | средняя | деградация скорости/превью | фолбэки уже в коде (`warmInternalsOf` → `null` → медленный путь); CI-прогон против свежего Remotion еженедельно |
| Обновление Claude Code CLI меняет поведение SDK | средняя | турны ломаются | пиннинг версии SDK, smoke-тест на канарейке до апдейта |
| «Сам соберу из исходников» съедает продажи | низкая | умеренный | принято сознательно; ценность Pro — время и контент, не замок |
| Один мейнтейнер | высокая | скорость, bus-factor | дисциплина scope: один этап за раз; hosted не начинать |
| Клон идеи более ресурсной командой | средняя | умеренный | скорость + реестр как ров (контент и SEO копировать дольше, чем код) |

## 7. Метрики

Этап B (бета): загрузки → доля дошедших до первого экспорта (главная метрика
онбординга; цель ≥ 40% при выполненных требованиях окружения) → недельный retention
сессий → количество экспортов на пользователя.

Этап C: конверсия бета-базы в Pro (ориентир 3–5%), выручка шаблонов vs лицензий,
доля продлений через год.
